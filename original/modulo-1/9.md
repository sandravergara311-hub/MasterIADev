Modelos locales y routing 🟢 — 7min
Antonio Perez
⏱ Lectura ~7 min · 🟢 Opcional (avanzada). No hace falta para el directo. Responde a una pregunta muy común: «¿puedo usar estos copilotos con modelos gratis, propios o en local?». Sí, con matices que conviene entender antes de intentarlo.

Hay tres formas de no depender de un único proveedor: un gateway que te da muchos modelos con una sola key (OpenRouter), modelos locales en tu máquina (Ollama, LM Studio), o herramientas multi-proveedor de fábrica (opencode). Las tres son reales. La pregunta útil no es «¿se puede?», es «¿cuándo compensa y qué pierdo?».

👥 ¿Para quién es esto?

Dev: te llevas cómo conectar cada herramienta a otros modelos y qué se rompe al hacerlo.

PM / founder: te llevas el criterio de coste/privacidad, sin el detalle de config.

No técnico: quédate con la idea final: para aprender esto, un modelo potente en la nube es la opción sensata; lo local es para casos concretos.

El gateway: OpenRouter
OpenRouter es una única API que da acceso a cientos de modelos de decenas de proveedores con una sola key y una sola URL base (https://openrouter.ai/api/v1, compatible con la API de OpenAI). Elige el más barato, hace fallback si uno falla y normaliza el formato para que no aprendas mil APIs distintas.

Precio: pasa el coste del proveedor sin markup sobre la inferencia (cobra un pequeño fee al comprar créditos). Bueno para comparar modelos sin darte de alta en cada proveedor.

Privacidad: por defecto no guarda tus prompts (solo metadatos); tienes flags por petición para denegar recolección de datos.

Es la capa más limpia si quieres experimentar con varios modelos sin fricción.

Correr modelos en tu máquina
Dos runners mainstream, ambos exponen un endpoint compatible con OpenAI en localhost:

Ollama: http://localhost:11434/v1. El más simple para descargar y servir modelos open.

LM Studio: http://localhost:1234/v1, con app de escritorio y un CLI (lms) para modo servidor.

Realidad de hardware (guía histórica de Ollama, hoy retirada del README pero útil como orden de magnitud, con cuantización ~4-bit): 7B/8B ≈ 8 GB de RAM, 13B ≈ 16 GB, 33B ≈ 32 GB, un 70B cuantizado ≈ 42 GB. El modelo tiene que caber en memoria o se parte entre GPU y CPU y se arrastra.

¿Puede cada herramienta usar otros modelos?
Aquí está el matiz que casi nadie te cuenta: se puede, pero casi siempre pagas algo a cambio.

Léelo así:

Claude Code está atado a modelos Claude. Apuntarlo a otro modelo es un router de comunidad (claude-code-router, LiteLLM), no soporte oficial. Anthropic lo dice literalmente: no soporta enrutar Claude Code a modelos no-Claude.

Cursor y Copilot te dejan traer tu key (BYOK), pero sacrifican piezas: Cursor pierde el autocompletado y anula el Zero Data Retention; Copilot lo permite en chat/agente pero no en el autocompletado.

opencode es el único multi-proveedor de fábrica: cambiar de modelo es una línea en su config. Es la herramienta donde explorar routing sin pelearte con el producto.

Cuándo compensa y cuándo es una trampa
⚠ La verdad incómoda (esto es el núcleo de la lección): los modelos open que igualan a los frontier en coding agéntico (por ejemplo Qwen3-Coder) son enormes, de datacenter. Los que caben en tu portátil (7B–33B) fallan justo en lo que este curso te enseña: tool-use fiable y contexto largo. Un principiante que ponga un modelo local pequeño y vea al agente romperse no sabrá distinguir «prompteé mal» de «mi modelo no sabe llamar herramientas». Eso sabotea el aprendizaje.

Compensa de verdad cuando:

Privacidad / código regulado: código que legalmente no puede salir de la empresa (local puro, o OpenRouter con Zero Data Retention).

Offline: sin conexión, el modelo local es la única opción.

Comparar y experimentar: OpenRouter para probar muchos modelos con una key.

Entender la fontanería: montar un gateway enseña cómo hablan estas herramientas con los modelos.

Es una trampa cuando lo usas para aprender agentic engineering: cambias un modelo potente y predecible por uno débil, y conviertes cada fallo en un misterio. La recomendación honesta: aprende sobre un modelo hosted potente, y cuando domines el flujo, si tienes una razón real (privacidad, coste, offline), baja a local sabiendo qué cedes.

📖 Glosario exprés

Gateway / router: un intermediario (OpenRouter) que te da muchos modelos por una API.

BYOK (bring your own key): usar tu propia API key del proveedor dentro de la herramienta.

Cuantización: comprimir los pesos del modelo (4-bit, 8-bit) para que quepa en menos memoria, a costa de algo de calidad.

Tool-use: la capacidad del modelo de llamar herramientas (leer, editar, ejecutar). Es lo que primero falla en modelos locales pequeños.

❓ Preguntas que quizá te estás haciendo

«¿Puedo usar Claude Code gratis con un modelo local?» Técnicamente vía router de comunidad, pero es un hack no soportado y pierdes caching/thinking. Si tu objetivo es multi-modelo, opencode es la herramienta pensada para eso.

«¿Un modelo local es "suficiente" para el curso?» Para aprender, no lo recomendamos: el riesgo es que confundas límites del modelo con errores tuyos.

«¿OpenRouter es más barato que ir al proveedor?» No añade markup a la inferencia; su valor es la comodidad (una key, muchos modelos), no un descuento.

Lo accionable de esta lección
Se puede usar otros modelos, pero cada herramienta cobra un peaje (Claude Code: no soportado; Cursor: pierde Tab/ZDR; Copilot: solo chat; opencode: de fábrica).

OpenRouter es la capa limpia para experimentar; local (Ollama/LM Studio) es para privacidad/offline.

Para aprender, modelo hosted potente: no metas la variable «modelo débil» mientras aprendes el flujo.

El coste real de lo local no es la RAM, es el tool-use poco fiable.
