Para montar el proceso automático
📖 Claude Code GitHub Actions (documentación oficial de Anthropic). Es la referencia para los dos modos de arranque, los parámetros disponibles y los permisos necesarios. Consulta especialmente quién puede disparar las ejecuciones y cómo gestionar los costes.

📦 anthropics/claude-code-action (repositorio). La carpeta examples/ contiene procesos completos para distintos escenarios. Partir de uno y adaptarlo suele ser más rápido que escribirlo desde cero.

📖 Code Review (documentación oficial de Anthropic). Describe la variante gestionada, que no requiere configurar un archivo de proceso. Consulta especialmente el apartado de precio y el archivo de instrucciones solo para revisiones, que muestra cómo configurar el comportamiento del revisor.

Para entender la plataforma que lo ejecuta
📖 About workflows (documentación de GitHub). Explica los conceptos básicos: eventos que disparan una ejecución, trabajos, pasos y ejecutores. Es una buena referencia para entender la estructura de un workflow antes de trabajar con ejemplos.

🔐 Using secrets in GitHub Actions (documentación de GitHub). Explica cómo almacenar credenciales para que un proceso automático pueda utilizarlas sin incluirlas en los archivos. También documenta qué ocurre con los secretos cuando un cambio procede de una copia externa del repositorio.

Para el fondo del asunto
📄 Lessons from Building Static Analysis Tools at Google, de Caitlin Sadowski, Edward Aftandilian, Alex Eagle, Liam Miller-Cushon y Ciera Jaspan. Communications of the ACM, volumen 61, número 4 (2018), páginas 58–66.

El artículo describe cómo Google integró herramientas de análisis estático en el trabajo diario de sus ingenieros. Es especialmente relevante por el criterio que utiliza para evaluar estas herramientas: no solo cuántas incidencias detectan, sino cuántas los ingenieros deciden corregir. El resumen del artículo menciona miles de incidencias corregidas cada día antes de integrar el código.

Si solo vas a leer una fuente de esta lista, empieza por esta.

💡 Un ejercicio de diez minutos que vale más que las cinco lecturas

Abre el archivo de instrucciones del agente de un proyecto que lleve un tiempo en marcha. Identifica las reglas de proceso que indican qué debe hacerse antes o después de modificar código.

Después, ve al repositorio y comprueba una por una si esas reglas se han cumplido durante las últimas semanas. No preguntes al agente: revisa el historial del repositorio.

Lo habitual es encontrar tres grupos: reglas que se cumplen de forma sistemática y podrían eliminarse; reglas que no se cumplen y no han tenido consecuencias; y una o dos que no se cumplen y pueden explicar problemas que hasta ahora atribuías a otras causas. Este último grupo te da una primera lista de qué merece la pena automatizar, basada en lo que ocurre realmente en el proyecto.
