Recursos 🟢 — 9 min
Antonio Perez
No hace falta para el directo. Está aquí para volver cuando un tema concreto sea tu cuello de botella, que es cuando aparecen las preguntas de detalle.

Todo es complemento, no requisito: lo imprescindible ya está en las lecciones obligatorias. Cuando algo es la documentación de quien fabrica la herramienta, se dice, porque un fabricante describiendo su producto es una fuente excelente para qué hace y una fuente interesada para cuánto conviene.

Por dónde empezar según tu perfil. Si eres dev, por SDD: teoría y filosofía. Si vienes de producto, por PRD y discovery. Y si solo tienes veinte minutos, los seis principios de Spec Kit más una plantilla de PRD de Lenny.

SDD: teoría y filosofía
⭐ GitHub Spec Kit: Spec-Driven Development (Core Principles). Los 6 principios de SDD.

📖 GitHub blog: Spec-driven development with AI: get started (sep 2025). Las 4 fases (Specify → Plan → Tasks → Implement).

📄 Paper, Piskala D.B.: Spec-Driven Development: From Code to Contract in the Age of AI Coding Assistants (arXiv 2026). Define los 3 niveles de rigor. ~30 min.

Thoughtworks: Spec-driven development, recogido como técnica emergente en su Technology Radar.

Microsoft Developer Blog: Diving Into Spec-Driven Development With GitHub Spec Kit. Visión enterprise; útil para vendérselo a tu equipo.

Visual Studio Magazine: GitHub Spec Kit Experiment: "A Lot of Questions". Análisis crítico, para la perspectiva de "no todo es perfecto".

PRD y discovery de producto
Marty Cagan: Inspired (SVPG). Cualquier guía sólida de PRD sirve; adáptala al flujo dirigido por especificación, donde el documento vive en el repositorio y la IA lo relee.

Lenny's Newsletter: Examples and templates of 1-Pagers and PRDs. Plantillas listas para usar. ⚠ Requiere suscripción de pago: el post está tras paywall.

Amplitude (métricas de éxito): North Star Playbook. La métrica-guía de resultado y sus inputs, para no caer en métricas de vanidad.

Kerry Rodden / Google (métricas de UX): The HEART framework for UX metrics. Cinco dimensiones (Happiness, Engagement, Adoption, Retention, Task success), del paper de ACM CHI 2010.

Backlog, criterios y estimación
📖 Mountain Goat Software (Mike Cohn): How to Use AI for Product Discovery and Writing Better User Stories. Prompts probados para personas, historias y criterios; descarga gratuita.

📖 Kollabe: AI-Assisted Backlog Refinement. El patrón de pedirle a la IA que agujeree lo escrito, en detalle.

📖 Cucumber: Writing better Gherkin. Criterios declarativos frente a imperativos: por qué el criterio de una historia es de negocio y no técnico.

📖 Liz Keogh: Acceptance Criteria vs. Scenarios. La distinción entre la regla y el ejemplo que la ilustra.

📄 arXiv: Story Point Estimation Using Large Language Models (Shetty et al., 2026). En zero-shot, sin datos de entrenamiento, los LLMs predicen story points mejor que modelos supervisados entrenados con el 80% del histórico.

📖 Faros AI: Understanding Sprint Velocity: What It Is and What It Isn't. La velocidad como herramienta de planificación, no como KPI.

📖 Scrum Guide oficial (2020): scrumguides.org. La definición de terminado y el objetivo del sprint como commitments.

Frameworks que implementan esta disciplina
El detalle profundo de un framework (instalación, comandos, specs delta) no hace falta todavía: aquí se aprende el orden, no la herramienta. Para cuando llegues:

OpenSpec: Fission-AI/OpenSpec. La recomendación del curso: ligero y pensado para sistemas que ya existen.

GitHub Spec Kit: github/spec-kit. Para la comparativa.

LIDR Specboot: LIDR-academy/lidr-specboot. Convenciones de LIDR sobre OpenSpec, con su comando de enriquecer historias.
