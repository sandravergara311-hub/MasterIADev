Qué hardware hace falta
Este módulo ejecuta dos modelos de lenguaje en tu ordenador, así que comprueba la memoria disponible antes de descargar nada. Así evitarás descargar varios gigas y descubrir después que no puedes ejecutarlos.

Consumo de memoria medido con todo en ejecución: los dos modelos ocupan 2,8 GB; el motor de contenedores y su base de datos, unos 0,8 GB; los tres proyectos juntos, menos de 0,2 GB. En total, unos 3,8 GB. Para saber si tienes suficiente, cuenta también la memoria que consumen las aplicaciones que ya tienes abiertas.

💡 Si tienes poca memoria disponible, puedes usar el modo ligero. El proyecto permite elegir qué modelo redacta las respuestas. Con el pequeño (qwen2.5:1.5b-instruct), los dos modelos consumen 1,8 GB en vez de 2,8 GB. En las mediciones, responde más del doble de rápido: tarda alrededor de un segundo en generar una respuesta, mientras que el modelo predeterminado tarda algo más de dos segundos. A cambio, cita con menos precisión los artículos de los que extrae la información. La próxima lección explica cómo activarlo al configurar el proyecto.

🪟 Windows: WSL solo dispone de la mitad de tu memoria
El Windows Subsystem for Linux (WSL) permite ejecutar Linux dentro de Windows. Es el entorno donde trabajarás en este módulo. Si usas Windows, revisa este apartado con atención: la instalación puede completarse sin problemas y fallar después al ejecutar el proyecto, sin que el error mencione WSL.

WSL 2 limita por defecto la memoria de Linux a la mitad de la RAM de tu equipo. Con 16 GB o más suele ser suficiente. Con 8 GB, Linux dispone de unos 4 GB, un margen demasiado ajustado para el ejercicio. Compruébalo en la terminal de Ubuntu con free -h, mirando el valor total de la fila Mem.

Para ampliar ese límite, crea un archivo llamado .wslconfig en tu carpeta de usuario (C:\Users\<tu-usuario>\.wslconfig). Por ejemplo, en un equipo con 16 GB de RAM, puedes asignar 12 GB a WSL:

[wsl2]
memory=12GB
Ajusta el valor a la memoria de tu equipo y deja margen para Windows. Después, ejecuta wsl --shutdown en PowerShell y vuelve a abrir la terminal de Ubuntu. También puedes cambiarlo desde WSL Settings, en el menú de inicio, sin editar archivos.

🚨 Elige dónde instalar Ollama según la memoria disponible.

Dentro de WSL, junto al proyecto: no necesitas configurar la red, pero los modelos consumen parte de la memoria asignada a Linux.

En Windows, fuera de WSL: los modelos no consumen la memoria asignada a Linux, pero el proyecto necesita una configuración de red adicional para encontrarlos. Por defecto, localhost dentro de WSL apunta al propio Linux. En Windows 11 22H2 o posterior, añade networkingMode=mirrored a la sección [wsl2] del mismo archivo y reinicia WSL con wsl --shutdown. Así podrás acceder a Ollama desde WSL mediante localhost.

Si tienes 16 GB o más, instala Ollama dentro de WSL: es la opción más sencilla de configurar.

Empieza por comprobar qué tienes ya
Abre una terminal y pega estos comandos tal cual. Si alguno devuelve «command not found» o «no se reconoce como un comando», esa herramienta no está instalada o la terminal no la encuentra.

docker --version
docker ps
ollama --version
python3 --version
node -v
make --version
Esto es lo que debes comprobar en cada respuesta:

docker --version muestra la versión instalada, por ejemplo Docker version 29.5.2, build 79eb04c.

docker ps comprueba si el motor de Docker está en ejecución. Si devuelve una tabla, aunque no tenga filas, está listo. Si aparece Cannot connect to the Docker daemon (...). Is the docker daemon running?, la terminal no consigue conectarse al motor. Comprueba que Docker esté arrancado.

ollama --version muestra ollama version is ... seguido del número de versión.

python3 --version muestra la versión de Python. Revísala con atención: si devuelve 3.9.x, encontrarás un problema más adelante. Su apartado explica cómo resolverlo.

node -v debe devolver v22.0.0 o superior. Dos de los tres proyectos del módulo necesitan Node. Si te falta, sigue las instrucciones para tu sistema en nodejs.org/en/download e instala la versión LTS (long-term support), que recibe soporte prolongado.

make --version muestra GNU Make seguido de un número. Make ejecuta los atajos incluidos en los tres proyectos para arrancarlos con un solo comando. Más abajo tienes su apartado, con indicaciones específicas para Windows.

Anota qué comprobaciones fallan y consulta sus apartados. Puedes saltarte los de las herramientas que ya estén listas.

Docker
Qué es. Una herramienta que ejecuta contenedores: entornos aislados que incluyen una aplicación y lo necesario para que funcione.

Para qué lo usa este módulo. Uno de los tres proyectos necesita PostgreSQL con una extensión concreta. Configurarlo a mano lleva tiempo; el proyecto incluye un archivo que permite arrancar la base de datos con todo preparado mediante un solo comando. Solo necesitarás saber cómo arrancarla y pararla.

Cómo instalarlo.

macOS y Windows: la opción habitual es Docker Desktop, disponible en docs.docker.com/desktop. Incluye el motor, la interfaz gráfica y docker compose.

Linux: basta con Docker Engine. Sigue las instrucciones para tu distribución en docs.docker.com/engine/install e incluye el complemento de Docker Compose.

🚨 Comprueba la licencia antes de instalar Docker Desktop en un equipo de empresa. Según su acuerdo de licencia, consultado en septiembre de 2026, es gratuito para uso personal, educación, proyectos open source no comerciales y pequeñas empresas con menos de 250 empleados y menos de 10 millones de dólares de facturación anual. Las empresas deben cumplir ambas condiciones. El uso profesional en organizaciones más grandes y en entidades públicas requiere una suscripción de pago.

Si tu organización necesita una suscripción, consulta con tu equipo: puede que ya tenga licencia. Si no la tiene, puedes usar otra herramienta compatible. Algunas alternativas habituales son Colima, Podman Desktop y Rancher Desktop, aunque pueden requerir configuración adicional. No se han probado con este proyecto, así que configúralas con antelación y comprueba que puedes ejecutar docker ps y los comandos docker compose del ejercicio.

⚠ Instalar Docker Desktop no basta; también tienes que abrirlo. Espera a que indique que el motor está listo antes de ejecutar los comandos del proyecto. Si aparece Cannot connect to the Docker daemon, la terminal no consigue conectarse al motor. Lo primero que debes comprobar es que Docker Desktop esté abierto y haya terminado de arrancar.

Ollama
Qué es: una herramienta que descarga modelos de lenguaje y los ejecuta en tu propia máquina para que otros programas puedan utilizarlos. Para ejecutar estos modelos en local, no necesitas clave de API (una credencial para acceder a un servicio) ni pagas por uso. Las consultas se procesan en tu ordenador.

Para qué lo usa este módulo: uno de los tres proyectos busca textos por su significado, sin limitarse a encontrar las palabras exactas que escribiste. Utiliza dos modelos pequeños en tu máquina, uno para la búsqueda y otro para redactar las respuestas, sin pagar por cada consulta.

Cómo instalarlo: encontrarás los instaladores oficiales en ollama.com/download:

macOS: descarga el instalador. Requiere macOS 14 Sonoma o posterior.

Windows: descarga el instalador. Requiere Windows 10 22H2 o posterior.

Linux: ejecuta este comando:

curl -fsSL https://ollama.com/install.sh | sh

Cómo comprobarlo: ollama --version muestra la versión instalada. ollama list muestra los modelos descargados; si acabas de instalarlo, es normal que la lista esté vacía.

🚨 Reserva espacio en disco y tiempo para las descargas. Los modelos se descargan una vez y quedan guardados. El de embeddings, que permite buscar por significado, ocupa cientos de megabytes; el que genera las respuestas, un par de gigabytes. Reserva al menos 3 GB libres. La próxima lección indica qué modelos descargar y con qué comandos. Hazlo con antelación: el tiempo de descarga depende de tu conexión y puede impedirte seguir el ejercicio si esperas al inicio de la sesión.

💡 La primera respuesta puede tardar más de lo esperado. Ollama necesita cargar el modelo en memoria antes de responder. En las mediciones realizadas en un portátil, la primera petición tardó unos veinte segundos; las siguientes, un par de segundos. El tiempo también depende del hardware y de cuánto trabajo pueda asumir la tarjeta gráfica. Una primera respuesta lenta no indica por sí sola un problema de configuración. Para medir la velocidad de respuesta, espera a que el modelo esté cargado.

Python: comprueba qué versión tienes
Qué es: un lenguaje de programación en el que está escrito uno de los tres proyectos. Necesitas su intérprete para ejecutarlo. No hace falta saber escribir Python, pero sí tener una versión compatible para instalar las dependencias y arrancar el proyecto.

No basta con tener Python instalado. En macOS, python3 puede apuntar a una versión antigua. Por ejemplo:

$ python3 --version
Python 3.9.6
Con esa versión, la instalación de las dependencias del proyecto falla. El error puede mencionar un conector de base de datos sin indicar que el problema es la versión de Python, lo que dificulta encontrar la causa.

Cómo instalar la versión probada: este proyecto se ha comprobado con Python 3.13. Puedes descargarlo desde python.org/downloads. En macOS también puedes usar Homebrew (brew install python@3.13); en Linux, consulta si está disponible en el gestor de paquetes de tu distribución.

Cómo comprobarlo: ejecuta python3.13 --version. Debe mostrar una versión 3.13.x. Usa el comando con el número de versión: instalar Python 3.13 no cambia necesariamente la versión que ejecuta python3.

make
Qué es: una herramienta que permite ejecutar secuencias de comandos mediante nombres cortos. Un archivo del proyecto define, por ejemplo, que setup comprueba la máquina, instala las dependencias, crea la configuración y prepara la base de datos. Tú escribes make setup en vez de recordar cada comando y su orden.

Para qué lo usa este módulo: los tres proyectos incluyen los mismos atajos: make check comprueba que tu máquina esté lista, make setup prepara el proyecto y make up lo arranca. Los usarás en la próxima lección, así que make debe estar disponible en tu terminal.

Cómo instalarlo:

macOS: viene con las herramientas de línea de comandos de Xcode. Instálalas con xcode-select --install.

Linux: puedes instalarlo con el gestor de paquetes de tu distribución. En Debian y Ubuntu está incluido en build-essential; también está disponible como paquete make.

Windows: para este módulo trabajarás en WSL, el entorno Linux dentro de Windows. Si aún no lo tienes, ejecuta wsl --install desde PowerShell abierto como administrador, siguiendo la guía oficial de Microsoft. Después, instala make dentro de Ubuntu con sudo apt update y sudo apt install make.

⚠ En Windows, comprueba make en la terminal donde trabajarás. Tenerlo instalado en Ubuntu de WSL no significa que esté disponible en PowerShell, ni al revés. Son entornos distintos, cada uno con sus programas. Abre el proyecto en WSL y ejecuta allí las seis comprobaciones del apartado «Empieza por comprobar qué tienes ya», no solo make --version.

📖 Glosario exprés. Seis términos que aparecen en esta lección:

Contenedor: un entorno aislado que incluye una aplicación y lo necesario para ejecutarla. Puedes crearlo y eliminarlo sin instalar sus dependencias directamente en tu sistema.

Motor de Docker (o daemon): el proceso que ejecuta los contenedores. Debe estar en ejecución para arrancarlos y gestionarlos.

Modelo local: un modelo que se ejecuta en tu ordenador en vez de en el servidor de un proveedor. En la configuración de este módulo, procesa las consultas sin enviarlas a un servicio externo y sin coste por uso.

Embedding: una representación numérica de un texto que permite comparar significados. Ayuda a encontrar textos sobre «cómo desplegar una aplicación» aunque escribas «puesta en producción» en el buscador, porque ambas expresiones se refieren a lo mismo.

Entorno virtual: una carpeta que mantiene separadas las dependencias de un proyecto de Python para evitar que se mezclen con las de otros proyectos.

Atajo de proyecto: un nombre corto (setup, up) definido en el proyecto para ejecutar una secuencia de comandos mediante make <nombre>. El atajo viene con el proyecto; la herramienta make se instala aparte.

❓ Preguntas que quizá te estás haciendo

«¿Voy a tener que pagar algo?» Ollama y Python son gratuitos y de código abierto. Docker Engine también es gratuito; Docker Desktop requiere una suscripción en los casos explicados arriba, donde encontrarás alternativas.

«¿Necesito una tarjeta gráfica potente para los modelos locales?» No. Los dos modelos se han elegido por su tamaño y consumen 2,8 GB de memoria en las mediciones realizadas. Pueden ejecutarse con el procesador, aunque responderán más despacio. Lo que sí puede impedir su ejecución es la falta de memoria disponible. Si usas Windows, revisa el límite de WSL explicado al principio.

«Trabajo en Windows. ¿Esto me sirve?» Sí. En este módulo trabajarás dentro de WSL para ejecutar los comandos del proyecto en Linux. Instala allí las herramientas que usarás desde esa terminal. Docker Desktop se instala en Windows y se conecta con WSL; Ollama también puede ejecutarse fuera de WSL con la configuración de red explicada al principio.

«¿Puedo saltarme Ollama y usar una API de pago?» No con la configuración prevista para este módulo. El proyecto utiliza un servidor local; conectarlo a otro servicio requiere cambios adicionales.

«Ya tengo Docker con otros contenedores en ejecución. ¿Habrá conflictos?» La base de datos del ejercicio usa un puerto distinto del habitual de PostgreSQL para evitar conflictos con otras instalaciones.
