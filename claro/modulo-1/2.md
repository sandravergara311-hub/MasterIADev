# Módulo 1 · Lección 2 — Los tres pilares importan lo mismo

Texto original: `original/modulo-1/2.md`  
Obligatoria. Léela antes de la clase en vivo.

## En una frase

Dos personas pueden usar el mismo modelo y obtener resultados distintos. La diferencia está en la herramienta, en la información que le das y en cómo le pides el trabajo. Las tres partes importan lo mismo.

## Palabras que vas a escuchar

- **Modelo frontier.** El modelo más capaz que una empresa tiene publicado en ese momento. No es un producto fijo. El nombre cambia cada pocos meses.
- **Benchmark.** Una lista de problemas de programación con respuesta conocida. Sirve para medir un sistema. El número depende tanto de cómo se arma la prueba como del modelo.
- **Harness.** También le dicen scaffolding. Es todo lo que rodea al modelo: qué archivos puede leer, qué comandos puede ejecutar, qué instrucciones lleva siempre y qué tiene prohibido. Eso convierte un modelo en un agente.
- **Copiloto agéntico.** La herramienta completa, no solo el modelo que trae adentro. Dos copilotos con el mismo modelo se comportan distinto si el harness es distinto.
- **Aceptación a la primera.** Qué parte del trabajo del agente se aprueba sin devolvérselo. Cada devolución es una vuelta completa de revisión.

## Caso real: la misma clínica, dos resultados

En Clínica Norte trabajan Marta y Pablo. Los dos usan el mismo modelo para el mismo cambio.

La regla del negocio es esta: el paciente puede cancelar una cita hasta 2 horas antes. Si falta menos tiempo, la cita se queda y se cobra el anticipo.

Pablo abre un chat vacío y escribe: "agrega la cancelación de citas". El agente crea un botón, borra la cita siempre, no mira la hora y no toca el cobro. El código compila. En recepción, una cancelación de último momento deja el hueco libre y no cobra el anticipo.

Marta tiene tres cosas que Pablo no tiene.

1. **Herramienta.** El agente puede leer el código y correr las pruebas. No puede tocar la carpeta de facturación sin pedir permiso.
2. **Contexto.** Un archivo corto dice la regla: el anticipo se cobra si se cancela con menos de 2 horas. La cita no se borra. Se marca como `cancelada`.
3. **Pedido.** El prompt dice cómo saber que ya terminó. Una prueba con una cita a 3 horas: se cancela y no se cobra. Otra con una cita a 30 minutos: no se cancela y el cobro queda registrado.

Mismo modelo. Misma clínica. Resultados distintos. La diferencia está fuera del modelo.

## El problema principal ya no es el modelo

Cada modelo nuevo promete que ahora sí vas a ir el doble de rápido. Las mediciones no confirman eso de forma automática. Hay estudios donde desarrolladores con experiencia van más lento en proyectos grandes. En otros, el trabajo se mueve de quien escribe a quien revisa.

Eso no significa que la IA no sirva. Significa que sirve cuando la herramienta, el contexto y el pedido están bien puestos. Quien espera que el modelo nuevo arregle solo el desorden, se queda en el mismo lugar.

Un dato para recordar: el mismo modelo puede sacar una nota alta en una prueba "limpia" y bajar decenas de puntos cuando la prueba se parece más al trabajo real. Por ejemplo, varios lenguajes y menos ayuda artificial. Mismo modelo. Mismo día. Cambia el auto, no el motor.

Birgitta Böckeler lo separa así. El modelo es el motor. El harness son las herramientas, las instrucciones, los sensores, los límites y la memoria. La frase que circula entre gente con experiencia es esta: diseña el harness, no solo el prompt.

## Los tres pilares

No van en escalera. Si descuidas uno, mejorar los otros no lo reemplaza.

**Pilar 1. La herramienta.**

No es solo "qué modelo usas". Es el modelo más el harness: qué puede leer y editar, qué comandos corre, qué reglas de seguridad tiene, si puede planear antes de tocar archivos, si puede delegar en otros agentes, y cómo se conecta con tu editor y con tus pull requests.

Un pull request es la propuesta de cambio que se revisa antes de unir el código.

El mismo modelo dentro de Cursor, de Claude Code o de una herramienta armada por ti no se comporta igual.

**Pilar 2. El contexto.**

Es lo que el modelo tiene delante cuando responde. "Puede abrir el proyecto" no es lo mismo que "el proyecto está dentro de la conversación". La calidad baja cuando el contexto crece, bastante antes de llenar el espacio. El contexto se elige, se recorta y se separa. A eso se le llama ingeniería de contexto.

**Pilar 3. El prompt.**

Es lo que escribes en cada turno. Es lo más visible. Entre gente con experiencia, es lo que menos marca la diferencia. Igual importa: define la tarea, cómo se comprueba y qué no se puede hacer. Pero un buen prompt, con un mal harness y un mal contexto, sigue saliendo mal.

Vuelve al ejemplo de la clínica. El prompt de Pablo era vago. Ese es el pilar 3. Además no tenía la regla de las 2 horas por escrito. Ese es el pilar 2. Y no tenía una prueba que se ejecutara sola. Ese es el pilar 1. Arreglar solo la redacción del prompt no habría alcanzado.

## No son tres épocas que se reemplazan

Se cuenta una historia cómoda. Primero se aprendió a escribir prompts. Después, a dar contexto. Ahora, a armar el harness. Y cada etapa deja atrás a la anterior.

El orden en que aparecieron es real. Tratarlos como tres épocas cerradas no lo es. Los tres siguen haciendo falta al mismo tiempo.

## Preguntas frecuentes

**Si el modelo no es el problema principal, ¿da igual cuál use?**

No. El modelo pone el piso. Por debajo de cierto nivel, no hay harness que compense. Los datos dicen otra cosa: con el modelo ya elegido, lo que lo rodea todavía mueve el resultado decenas de puntos. El modelo se elige cada varios meses. Cómo lo rodeas se decide en cada tarea.

**¿Los tres pilares no son solo "úsalo bien"?**

Sirven porque cada uno falla distinto y se arregla distinto. Si el agente ignora las reglas del proyecto, un prompt más elegante no lo arregla. Si la herramienta no puede ejecutar comandos, más contexto no lo arregla. Sirven para saber dónde estás perdiendo tiempo.

**Si las mediciones de productividad se contradicen, ¿por qué creerles?**

Por el patrón, no por un número suelto. Las mismas capacidades, en condiciones distintas, dan resultados distintos. Cualquier número, también los de esta lección, mide unas condiciones concretas. No es una propiedad eterna del modelo.

## Qué llevarte

- El modelo no explica solo la diferencia entre dos personas que usan la misma herramienta.
- El harness explica saltos grandes en pruebas parecidas.
- Los tres pilares importan lo mismo.
- Lo que sí se lleva a otra herramienta es esta forma de pensar. Los atajos de un producto, no.
