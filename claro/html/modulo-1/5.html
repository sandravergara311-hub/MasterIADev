Módulo 1 · Lección 5 — Deja la computadora y las cuentas listas

Texto original: original/modulo-1/5.md
Obligatoria. Leerla es poco. Hacerla toma tiempo. No la dejes para la noche anterior.

En una frase

Esta lección no enseña una idea. Es la lista de lo que tiene que estar instalado para trabajar en las clases en vivo. Casi todo se hace una sola vez.

Si algo se traba más de veinte minutos, para y avísale a tu TA. Casi siempre es un detalle del sistema, no un concepto que se te escapa.

Caso real: la clase perdida por un comando

Ana llega a la clase en vivo con el código abierto en el editor y sin terminal. A los diez minutos el ejercicio pide make setup. En PowerShell, make no existe. Pierde la clase instalando cosas, mientras el resto ya compara dos copias del proyecto.

La lección es esa: revisa hoy, en la terminal donde de verdad vas a trabajar.

Empieza por lo que ya tienes

Abre una terminal y pega esto. Cada línea debería responder con un número de versión. La que diga que no reconoce el comando es la que te falta.

git --version
node -v
claude --version
gh --version
make --version

Salta los apartados que ya respondan.

  • Si ya vives en la terminal, probablemente tengas la mitad. Lo que casi nadie trae listo es la cuenta de Atlassian.
  • Si programas solo dentro del editor, lo nuevo será la terminal y la clave SSH. No es difícil. La primera vez toma tiempo.
  • Si no vienes de tecnología, reserva una tarde y sigue el orden. Cada apartado dice qué es la herramienta, no solo cómo se instala.

Git y GitHub

Git guarda el historial de cambios del código. GitHub es el sitio donde está el repositorio del curso. El material de práctica se descarga y se sube por ahí.

Instalación: git-scm.com/downloads. En macOS llega con las herramientas de Xcode (xcode-select --install). En Linux, con el administrador de paquetes. En Windows, Git for Windows. Ese instalador también deja Git Bash.

La parte que se traba es demostrar que eres tú. Si no lo dejas resuelto, el día del git push vas a ver Permission denied (publickey).

Camino A, clave SSH. Es una pareja de archivos. Subes la mitad pública a GitHub.

ssh-keygen -t ed25519 -C "tu-correo@ejemplo.com"
cat ~/.ssh/id_ed25519.pub
ssh -T git@github.com

La guía oficial está en conectar con SSH. Si responde Hi USUARIO!, ya está. Nunca subas el archivo que no termina en .pub.

Camino B, HTTPS. Usas direcciones que empiezan con https://github.com/... y dejas que gh guarde tus credenciales. Sirve igual.

git@github.com:usuario/repo.git y https://github.com/usuario/repo.git son el mismo sitio. Lo que no sirve es no elegir uno.

Node.js

Es el programa que ejecuta JavaScript y TypeScript fuera del navegador. El proyecto del curso corre sobre él. Varias herramientas se instalan con npm.

Instala la versión LTS desde nodejs.org/en/download. Esta lección pide como mínimo v20.19. Más adelante, el ejercicio del módulo 2 pide Node 24. Si vas a hacer los dos, instala ya la 24 LTS y te ahorras el susto.

Si ya tienes un Node viejo que usa otro proyecto, no lo reemplaces a mano. Usa un administrador de versiones.

Claude Code

Es el copiloto con el que se trabaja en el curso. Va en la terminal, lee el proyecto y ejecuta comandos con tu permiso.

Instrucciones: code.claude.com/docs. La primera vez, claude te manda al navegador para identificarte. Revisa con claude --version.

No está en el plan gratuito de Claude. Mira el precio en la página oficial, porque cambia. Si tu empresa tiene licencias, pregunta ahí primero.

Para trabajar en tu computadora no necesitas una clave de API de Anthropic. claude entra con tu cuenta. Existe claude setup-token para automatizaciones en las que tú no estás delante. Hoy no hace falta prepararlo.

gh, la terminal de GitHub

Sirve para crear pull requests, ver una revisión y leer un diff sin abrir el navegador. Un diff es la diferencia entre dos versiones del código.

El curso la usa por dos motivos. Te ahorra saltar a la web. Y el agente ya sabe usar gh. Eso gasta menos contexto que conectarle un servidor entero de herramientas solo para leer un diff.

Instalación: cli.github.com. Después, y esto se olvida:

gh auth login
gh auth status

Ahí eliges SSH o HTTPS. Si eliges HTTPS, te ofrece guardar las credenciales de Git. Guía: GitHub CLI quickstart.

make

Es un lanzador de atajos. El proyecto dice: "setup significa instalar, crear la configuración y preparar la base de datos". Tú escribes make setup en lugar de recordar cuatro comandos.

  • macOS: xcode-select --install
  • Linux y Ubuntu en WSL: sudo apt install make
  • Windows: el camino del curso es WSL. Es un Linux que corre dentro de Windows. Se instala con wsl --install desde PowerShell como administrador. Guía de Microsoft.

Revisa make --version en la terminal donde vas a abrir el proyecto. En Windows es fácil que responda dentro de Ubuntu y no en PowerShell. Son dos ambientes. Lo que instales en uno no aparece en el otro.

Jira, en un sitio tuyo

Jira es el tablero de tarjetas. El curso lo usa para que el mismo trabajo exista donde un equipo lo seguiría de verdad, y para que el agente cree esas tarjetas.

El alta en el plan Free no pide tarjeta: atlassian.com. Confirma el correo.

El subdominio (elnombre.atlassian.net) en el plan gratuito no se cambia después sin un plan de pago. Elige uno que puedas mostrar dentro de un año. No uses el nombre de tu empresa si esto es un sitio de prueba.

Crea un tablero con plantilla Kanban o Scrum. Nombre: FlowSync. Clave: FLOW. Jira la propone a partir del nombre. Si sale otra, cámbiala hoy en los detalles del espacio. Los prompts del curso esperan FLOW. Cambiarla a mitad del ejercicio deja medio tablero con la clave equivocada.

Atlassian cambió palabras y la pantalla ya no coincide con muchos textos:

  • issue pasó a work item en marzo de 2025,
  • project pasó a space en septiembre de 2025.

Es lo mismo. Las APIs y el lenguaje de búsqueda siguen diciendo issue.

Mira cómo se llaman tus tipos. En un sitio en español pueden convivir "Historia" y "Tarea" con "Epic" y "Subtask" en inglés. Anota cómo se llama la historia de usuario y si hay subtareas. Los prompts le preguntan a Jira qué tipos existen. Tú tienes que poder confirmar que el agente eligió bien, antes de que cree medio tablero.

La conexión del agente es por MCP. Es el enchufe estándar para que el copiloto hable con un sistema de afuera. El servidor oficial de Atlassian funciona en el plan Free, con un límite de llamadas por hora. En Free, del orden de 500 por hora. No lo confundas con Rovo, el producto de IA de pago. La tabla de precios de Rovo no es la página del servidor MCP.

Si alguna conexión pide un token, se crea en id.atlassian.com. Trátalo como una contraseña. No lo subas al repositorio.

Un sitio gratuito que nadie usa se puede desactivar por inactividad.

Si ya usas Jira en tu empresa y no puedes crear tableros, elegir la clave o conectar herramientas externas, abre un sitio gratuito propio. No hagas pruebas sobre el tablero real del equipo.

Palabras sueltas

  • CLI. Un programa que se usa escribiendo, no haciendo clic. git, gh, make y claude lo son.
  • Terminal. La ventana donde escribes esos comandos.
  • SSH. Te identificas con una pareja de claves, no con una contraseña. La pública se sube. La privada no sale de tu computadora.
  • WSL. Un Linux dentro de Windows, con sus propios programas.
  • MCP. El conector estándar para que el copiloto hable con un sistema de afuera, como Jira o una base de datos.
  • Token de API. Una cadena que reemplaza tu usuario y tu contraseña cuando se conecta un programa. Se puede anular sin cambiar la contraseña.

Antes de cerrar

Vuelve a correr las cinco revisiones. Si responden con una versión, la computadora está lista. Si además entraste al tablero, la clave es FLOW y sabes cómo se llaman los tipos, las cuentas también están listas.

Lo que quede en rojo, dilo hoy. Un problema de instalación con la clase ya empezada es una sesión perdida.
