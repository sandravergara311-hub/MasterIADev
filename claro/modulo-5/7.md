## Para montar el proceso automático

- Claude Code GitHub Actions, documentación oficial de Anthropic. Es la referencia de los dos modos de arranque, los parámetros y los permisos. Mira sobre todo quién puede disparar las ejecuciones y cómo se gestionan los costos.
- El repositorio `anthropics/claude-code-action`. La carpeta `examples/` tiene procesos completos para distintos escenarios. Partir de uno y adaptarlo suele ser más rápido que escribirlo desde cero.
- Code Review, documentación oficial de Anthropic. Describe la variante gestionada, que no pide configurar un archivo de proceso. Mira el apartado de precio y el archivo de instrucciones solo para revisiones.

## Para entender la plataforma que lo ejecuta

- About workflows, documentación de GitHub. Eventos que disparan una ejecución, trabajos, pasos y ejecutores. Sirve para entender la estructura de un workflow antes de trabajar con ejemplos.
- Using secrets in GitHub Actions, documentación de GitHub. Cómo guardar credenciales para que un proceso automático las use sin incluirlas en los archivos. También documenta qué ocurre con los secretos cuando un cambio viene de una copia externa del repositorio.

## Para el fondo

*Lessons from Building Static Analysis Tools at Google*, de Caitlin Sadowski, Edward Aftandilian, Alex Eagle, Liam Miller-Cushon y Ciera Jaspan. Communications of the ACM, volumen 61, número 4 (2018), páginas 58–66.

El artículo describe cómo Google integró herramientas de análisis estático en el trabajo diario de sus ingenieros. El criterio que usa para evaluarlas no es solo cuántas incidencias detectan. Es cuántas los ingenieros deciden corregir. El resumen menciona miles de incidencias corregidas cada día, antes de integrar el código.

Si solo vas a leer una fuente de esta lista, empieza por esta.

## Un ejercicio de diez minutos

Abre el archivo de instrucciones del agente de un proyecto que lleve un tiempo en marcha. Identifica las reglas de proceso: qué debe hacerse antes o después de modificar código.

Después ve al repositorio y comprueba, una por una, si esas reglas se cumplieron durante las últimas semanas. No le preguntes al agente. Revisa el historial.

Lo habitual es encontrar tres grupos.

- Reglas que se cumplen de forma sistemática y podrían eliminarse.
- Reglas que no se cumplen y no han tenido consecuencias.
- Una o dos que no se cumplen y pueden explicar problemas que hasta ahora atribuías a otras causas.

Ese último grupo te da una primera lista de qué merece automatizarse, basada en lo que ocurre de verdad en el proyecto.
